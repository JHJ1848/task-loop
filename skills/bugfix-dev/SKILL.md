# 开发与修复

1. **查现状。** 通过 [memory-get](../memory-get/SKILL.md) 读相关规则与记忆，沿入口、数据流和持久化核对实际行为。有兼容疑点再查相关提交和变更记录，标明事实与推测。
2. **定范围。** 开发先明确目标、白名单和验收。缺陷先复现，按宿主、数据、代码的顺序核实根因；用[排查手册](references/troubleshooting-playbook.md)选择验证方法。需求、根因或写入授权存在关键疑问时先对齐。
3. **实施。** 保持现有调用、业务规则和数据兼容性，限于白名单。并发写入、异常处理和软删除等行为按[实施要点](references/implementation-and-verification.md)复核。代码只为关键约束和公共契约补充必要注释。
4. **验证并交付。** 重跑原问题和相关路径，核对 Diff 及验收条件。优化要给前后对照。需要人工验证时给出操作和预期，部署或宿主验证另记结果。按项目要求独立审查，经用户确认后用 `memory-put` 归档。

保留无关改动。发现超范围、关键不变量失效或现有证据无法区分根因时，回报证据再继续。通用约束见[工程原则](../../rules/engineering-principles.md)，复杂排障用[根因卡](references/root-cause-analysis-card.md)。
